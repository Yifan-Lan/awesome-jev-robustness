# Contributing

Add one line in the section that fits, in a pull request. The list is deliberately narrow: an entry has to show how Jev's answer or probability changes with wording, options, order, repetition, language, planted text or unanswerable input, or test whether the probability is calibrated. A task benchmark that only reports an accuracy belongs in `data/task_benchmarks.tsv`, not in the README. Keep the format of the lines around it:

    - [name](url) - What was measured, on how many items, and the headline number.

An entry needs all three of these, or a link to a page that has them:

- what it measured about Jev's behavior, not just that it uses Jev;
- which model version it hit (`jev-1.13.0`, `jev-latest` on a given date, or the gateway name);
- how many items were run.

Things that do not go here: tools, SDKs, applications, general project directories, open reproductions that do not compare themselves against Jev. There are good lists for those, linked at the bottom of the README.

Descriptions are plain statements of what the authors report. No adjectives about how impressive the result is. If the authors state a caveat (small sample, labels generated by another model, no baseline), the description should carry it.

If an entry describes your work incorrectly, open an issue or a pull request with the correction and a pointer to where the right number is. If you would rather not be listed, say so and the entry will be removed.

Entries that could not be confirmed to contain measurements are kept in `data/candidates_unconfirmed.tsv` rather than the README. Confirming one of them, with a link to the numbers, is a welcome pull request.
